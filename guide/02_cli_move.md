# 02. CLI で動かす

コードは書かず、`ros2 topic pub` でロボットにメッセージを送って動かす。ステップ1は「ロボット → PC」の向き、今回は「PC → ロボット」の向き。

## ゴール
- `ros2 topic pub` で、型に合わせたメッセージを送ってロボットを動かせる
- 「送ったメッセージがどう動きに変わるか」を観察する

## コマンドの形
```bash
ros2 topic pub [オプション] <トピック名> <型> "<中身（YAML）>"
```
| オプション | 意味 |
|---|---|
| `--once` | 1回だけ送って終了 |
| `-r 10` | 1秒に10回送り続ける（`Ctrl+C` で停止） |

中身は、ステップ1で `ros2 interface show` を使って見たフィールドを YAML で書く。例：`UInt16` なら `"data: 300"`。

## 1通だけだと届かないことがある
```
ros コンテナ ──(PC内・DDS・RELIABLE)──▶ agent ──(WiFi・UDP)──▶ ESP32
               取りこぼしなし                    ここで落ちることがある
```
- `--once` で送った `beep 1` や `beep 0` が届かないことがあった
- 何回送っても結果が同じ命令（`beep 0`、サーボ角度、停止）は **`-t 3`（3回送る）** を使う
- 走行指令は一定周期で送り続けるのが ROS の定番（1通落ちても次で補われる）

## 安全のために
- **走行（③）を試す前に、車輪を浮かせる**（箱の上に載せるなど）
- 止めたいときは、すぐに停止コマンド（③-3）を送る。念のため別のターミナルに準備しておく

## やること
`ros` コンテナのシェルで1つずつ実行する。

### ① ブザー（`/beep`, `std_msgs/msg/UInt16`）
| # | コマンド | 確認すること |
|---|---|---|
| 1-1 | `ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 300"` | 0.3秒鳴って自動で止まる |
| 1-2 | `ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 1"` | 鳴り続ける |
| 1-3 | `ros2 topic pub --once /beep std_msgs/msg/UInt16 "data: 0"` | 止まる |

### ② サーボ（`/servo_s1`, `/servo_s2`, `std_msgs/msg/Int32`）
| # | コマンド | 確認すること |
|---|---|---|
| 2-1 | `ros2 topic pub --once /servo_s1 std_msgs/msg/Int32 "data: 30"` | どちらの向きに動くか |
| 2-2 | `ros2 topic pub --once /servo_s2 std_msgs/msg/Int32 "data: -30"` | どちらの向きに動くか |
| 2-3 | `s1`・`s2` とも `"data: 0"` を送る | 正面に戻る |

範囲は S1 が [-90, 90]、S2 が [-90, 20]。範囲外の値は送らない。

### ③ 走行（`/cmd_vel`, `geometry_msgs/msg/Twist`）※車輪を浮かせて
| # | コマンド | 確認すること |
|---|---|---|
| 3-1 | `ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.1}}"` | 車輪が前進方向に回る。**1回送っただけで回り続けるか、止まるか** |
| 3-2 | `ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{angular: {z: 0.5}}"` | 左右の車輪が逆に回る（その場で左旋回） |
| 3-3 | `ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"` | 停止（全フィールドが 0） |

- `Twist` は `linear`（並進 [m/s]）と `angular`（回転 [rad/s]）の2つの Vector3 からなる
  - `ros2 interface show geometry_msgs/msg/Twist` で確認する
- 書かなかったフィールドは 0 になる
- REP 103 の規約で、`linear.x` が前、`angular.z` が正のときは左回り（上から見て反時計回り）

### ④ 送ったものを観る
別のターミナルで `ros2 topic echo /cmd_vel` を開いたまま、③を送ってみる。自分が送ったメッセージがトピックに流れるのが見える。

## 結果メモ
| 項目 | 結果 |
|---|---|
| ブザー | 300 で 0.3 秒鳴る。1 で鳴り続け、0 で止まる（ただし1通では届かないことがあった） |
| サーボ | **絶対角度の指定**（相対ではない） |
| S1（首振り） | **+ が右**、− が左、0 が正面 |
| S2（うなずき） | **+ が上**、− が下。上側は +20 まで（本体に当たるため？） |
| 走行 | 3-1〜3-3 は予想どおり動いた。単位は `linear` が m/s、`angular` が rad/s（REP 103 の SI 単位） |
| 走行の持続 | **`--once` で1回送っただけで回り続けた**。最後の指令を新しい指令が来るまで続ける（タイムアウトで止まらない） |

- 型からわかるのは**形式**だけ。値の**意味**（絶対か相対か、+ の向き）はメーカー資料と実験で確かめる
- 仮説を立てて → 送って → 観察する（例：S2 が「-30 でも 0 でも上に動いた」のは、初期位置が -30 より下だったため）
- 走り続ける性質があるため、自作コードでは **終了時に停止を複数回送る**、**走行中は周期的に送り続ける** の2点が必須
